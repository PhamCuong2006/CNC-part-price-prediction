# CNC Part Price Estimator

Predicts a quote price for a machined part from its STEP CAD geometry plus
operator-entered process inputs, using a trained XGBoost regression model.
Includes a Streamlit app for interactive quoting.

## Contents

| File | Purpose |
|---|---|
| `data.csv` | Training dataset - one row per historical quoted part (313 rows, 22 columns) |
| `step_features.py` | Extracts geometry features (dimensions, volume, area, hole/slot counts) from a parsed STEP shape via CadQuery/OCP |
| `geometry.py` | Validates STEP uploads (extension, size, header, application protocol) and wraps `step_features` for the app - `load_geometry()` for prediction, `load_mesh()` for the 3D preview |
| `features.py` | The model's feature contract: raw -> engineered feature transform, material -> material-family mapping, target extraction |
| `train_model.py` | CLI that trains the XGBoost regressor on `data.csv` and writes `artifacts/` |
| `streamlit_app.py` | Interactive app - upload a STEP file, fill in process inputs, get a price |
| `artifacts/` | Trained model (`model.json`) and its metadata (`metadata.json`), generated by `train_model.py` |

## How it fits together

A STEP upload is read by `step_features.py` (raw geometry) after `geometry.py`
validates and wraps it; the operator's process inputs (material, tolerances,
complexity, quantity, ...) are collected alongside it. `features.build_features`
turns both into the model's engineered feature row. `train_model.py` runs this
same transform over every row of `data.csv` to fit the model; `streamlit_app.py`
runs it over one uploaded part to score it.

## Setup

- Python 3.14
- A virtual environment already exists at `../.venv` with dependencies installed
  (no `requirements.txt` / `pyproject.toml` is checked in yet):
  - pandas 3.0.3, numpy 2.5.1, scikit-learn 1.9.0, xgboost 3.4.0
  - streamlit 1.61.1, plotly 6.9.0
  - cadquery 2.8.0 (STEP parsing, via OCP/OCCT)

Activate it (PowerShell):

```powershell
..\.venv\Scripts\Activate.ps1
```

`features.py`, `geometry.py` and friends import each other as flat modules
(`from features import ...`), so run everything below with `src/` as the
working directory.

## Usage

### Train the model

```powershell
cd src
python train_model.py                 # reads data.csv, writes artifacts\
python train_model.py --data <path> --output-dir <path>   # override either default
```

Prints train/test MAE, RMSE, MAPE, R2 and weighted MAPE, then writes
`artifacts/model.json` and `artifacts/metadata.json`.

### Run the app

```powershell
cd src
streamlit run streamlit_app.py
```

Upload a `.step`/`.stp` file (AP203, AP214 or AP242 - a machined mechanical
part, not an assembly/electronics/plant export), fill in the process inputs,
click **Generate price**.

## Model

- `XGBRegressor`, 300 trees, depth 4, `reg:squarederror` trained on
  `log1p(price)` (price capped at the training set's 97th percentile before
  the log transform; predictions are inverted with `expm1`).
- `material_family` (5 levels: Aluminum, Carbon Steel, Plastic, Stainless
  Steel, Titanium) is the only material signal the model sees - the ~26 raw
  material grades in `features.MATERIAL_TO_FAMILY` collapse into it.
- `special_type` and `specialized_tool` are collected in the app and recorded
  with the quote, but aren't model inputs: the training data has a single
  value for each, so they carry no signal.
- Current snapshot (`artifacts/metadata.json`, trained 2026-08-17,
  n_train=250 / n_test=63): test MAE $187, test MAPE 42.9%, R2 0.847. This is
  one fixed 80/20 split (`random_state=42`) over a modest dataset, so treat it
  as indicative rather than a precise measurement - rerun `train_model.py` to
  refresh it.
- `n_holes`/`n_slots` from `step_features.py` are a geometric heuristic
  (grouping cylindrical/conical faces by shared axis), not exact feature
  recognition - see that module's docstrings for the known edge cases.
